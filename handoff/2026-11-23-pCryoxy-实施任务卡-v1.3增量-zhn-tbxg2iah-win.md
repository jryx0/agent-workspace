## 3. PC-04c 节点出站纳管（新增 P0）

- **依据**：REQ-08（协议、传输、安全分别建模，按固定核心建立支持矩阵）；人类 11-22「不接受 P0 缩减」；人类 11-23 19:30 裁定。
- **背景**：11-21 受限子集裁定的规则是「没列出来的出站一律拒绝」，PC-04b 只补回了 freedom、sniffing、FinalMask、DNS 四项。结果桥的启动阶段只放行 `freedom`、`proxy/dns`（`restricted_profile.go:322-326`）；运行阶段没有增删出站的接口（`runtime.go:47`，Control 服务只有 QueryState/ReplaceRoutes/ReloadGeo/Rollback/QueryOperation/ReleaseRollbackPoint 六个 RPC）。
- **依赖**：PC-04b done。可以和 PC-07 并行。
- **文件归属**：
  - `native/xray-bridge/restricted_profile*.go`（出站准入）、`route_control.go`（出站和路由的同 epoch 提交）、`runtime*.go`（出站管理）及新增的桥内文件；
  - `tests/integration/bridge/`；`upstream-patches/` 只允许新增序号，不改已审补丁。
  - **契约文件**：`native/xray-bridge/core_control.proto`、`crates/plugin-xray/proto.lock`、`crates/plugin-xray/proto/descriptor.pb`，以及 `core_control*.pb.go` 生成物。这些文件只有在 **Control 服务接口变更申请** 获人类批准后才能修改。
  - 不改 ABI v2 的 C 符号和 296-byte status 结构。go.mod 若要新增依赖，先申请。
- **第一步（实施之前）**：在 handoff 写「Control 服务出站接口变更申请」，内容包括：
  - 新 RPC 的形式。审核方建议用一次提交整组出站集合的方式（比如 `ReplaceOutbounds`），或者把出站和路由合并成一次提交，而不是逐个 Add/Remove。
  - 请求体是 JSON 出站配置，由桥用固定核心的 `infra/conf` 构建器转换成核心配置。这样 XMC 的 RSA 派生等逻辑留在 Go 核心里，Rust 侧不需要密码学依赖。
  - 和 RouteView 的 epoch、回滚点的关系；路由引用了不存在的出站 tag 时，提交必须失败。
- **启动阶段准入范围**（逐项从拒绝清单移到允许清单，每项单独取证）：
  - 协议：vless（含 Vision、VLESS Encryption）、vmess、trojan、shadowsocks（含 2022）、hysteria2、wireguard、masque；
  - 传输：raw、xhttp、ws、httpupgrade、grpc；
  - 安全：tls、reality；
  - FinalMask：复用 PC-04b 的白名单校验。
- **一律拒绝**：代理链（`proxySettings`/dialerProxy 指向其他出站）；`sockopt` 中可能绕过 RouteView 的选项（如 `mark` 以外的接口绑定、非 AsIs 的 `domainStrategy`，以实测为准）；`mux` 是否放行，在申请里单独论证；被 PC-04b 拒绝的 FinalMask 类型；固定核心不支持的组合。
- **验收**：
  1. 每个协议、传输、安全选项都要有：prepare 允许、与本地受控服务端互通（可以和 PC-07 的夹具共用）、未纳管的变体在 prepare 被拒且 active 状态不变；
  2. 运行时出站提交和路由同 epoch：publish 和 rollback 下单 epoch 证据（含 `-race`），引用缺失 tag 的提交失败、active 状态不变；
  3. 运行时提交的校验规则和启动阶段一致（同一套校验函数，有测试证明）；
  4. 不引入 SetAdmission 或新的流门禁；PC-04/04b 的全部回归测试继续通过；
  5. Windows 原生、Linux（含 `-race`）、Android 交叉构建都通过；凭据不进日志和 fixture；Gitleaks 无发现。
- **下游**：PC-07 的两栏取证、PC-08 运行时同步、PC-12。

### 3.1 追加：默认拒绝出站纳管（人类 2026-11-23 20:08 裁定）

- **缺口**：Xray 把未匹配任何路由规则的流量交给第一个出站。蓝图 §326 规定第一个出站是常驻 blackhole `sys/reject`，但桥不允许 blackhole，能通过 prepare 的配置第一个出站只能是 freedom，即未匹配流量走直连（fail-open）。PC-04b 卡面与审核遗漏。PC-04c 放开节点出站前必须先堵上。
- **要求**：
  1. 启动阶段放行 blackhole 出站，response 只允许 none（不填或显式 none），其他 response 类型拒绝。
  2. prepare 强制：第一个出站必须是 blackhole 且 tag 为 `sys/reject`，否则拒绝（fail-closed）。
  3. `sys/reject`、`sys/direct` 不可删除、不进动态池；运行时出站整组提交必须保留二者，删除或替换它们的提交失败，active 状态不变。
- **验收追加**：未匹配任何规则的流量被拒绝（不走直连）；第一个出站不是 `sys/reject` 的配置被拒；运行时删除或替换 `sys/reject`/`sys/direct` 的提交失败且 active 不变。PC-04/04b 夹具中第一个出站为 freedom 的，按新规则修改测试夹具，改动范围在交付报告中列清。
- **PC-07**：照常生成 `sys/reject` 作为第一个出站；「桥 prepare」栏标「待 PC-04c」。
