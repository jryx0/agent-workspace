## 三、RL-001 任务卡：`env/rules-lint.sh`

**认领**：先在 `memory/projects/global.md` 任务登记节追加认领行，再开工。

本任务要写 `~/.agent-shared/env/`，属于 T2：开工前先完成自检简报；不得在 `~/.agent-shared` 用 worktree（三-6）。

**目的**：拆分后规范正文分布在 `global/rules.md` 与 `global/spec/*.md` 两处，常驻层留有锚句摘要。本脚本用机器核对两侧是否漂移，以及注入端红线是否同步。规范修订提交前运行（v2.6 第十节「机器校验」）。

**硬约束**

1. **只读**：不写任何文件，不发网络请求，不执行任何 git 写操作（含 pull / fetch）。
2. **可移植**：bash + POSIX `grep / sed / awk / wc`；Windows Git Bash、macOS、Linux 均可运行。不依赖 Python，不装任何依赖。
3. **字符数口径**：按 Unicode 字符计数（`wc -m`，须在 UTF-8 locale 下，例如 `LC_ALL=C.UTF-8`，不可用时回退 `en_US.UTF-8`）。脚本要先自测 locale：`printf '中' | wc -m` 应为 1，否则报错退出，不能静默算成字节数。
4. 退出码：0 = 全部通过；1 = 有失败项；2 = 参数或环境错误。每项检查输出 `PASS/FAIL 编号 说明`，失败项给出文件名与具体文本。

**参数**（默认值即落地后的正式位置）

```
bash env/rules-lint.sh [--rules global/rules.md] [--spec global/spec] [--l1 env/execution-enforcement.md]
```

路径相对 `~/.agent-shared`。对候选稿的运行方式：

```
--rules tmp/workbuddy/2026-11-12-rules-v2.6/rules.draft.md
--spec  tmp/workbuddy/2026-11-12-rules-v2.6/spec
--l1    tmp/workbuddy/2026-11-12-rules-v2.6/execution-enforcement.draft.md
```

**检查项**（语义参考 `tmp/workbuddy/2026-11-12-rules-v2.6/_build/check.py`，用 bash 重写，不要调用它）

| 编号 | 检查 |
|---|---|
| C1 锚句 | 每份分卷末尾 `<!-- anchors：… -->` 块里，每行 ` \| ` 后的文本须在**该分卷注释块之外**恰好出现 1 次，并在 `--rules` 文件中至少出现 1 次。逐字比较，用 `grep -F`，不做空白归一。 |
| C2 原编号 | 每份分卷前 6 行内有 `> **原编号**：` 行。 |
| C3 指针 | `--rules` 中所有 `` `spec/X.md` `` 与 `` `global/spec/X.md` `` 指向的文件都存在；其后紧跟的「`（N 字符`」或分流表「`\| N`」与实际字符数相等。每份分卷至少被 `--rules` 引用一次。 |
