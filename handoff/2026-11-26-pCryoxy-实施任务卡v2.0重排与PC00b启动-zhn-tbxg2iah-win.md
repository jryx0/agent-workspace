# pCryoxy 实施任务卡 v2.0（M0～M5 垂直切片重排）与 PC-00b 启动

## 1. 背景与人类裁定（2026-11-26 08:41 UTC+8）
基于前期架构自洽性、里程碑与四语言代码库审查结论，并结合人类明确的两个最高优先级诉求：
- **优先级 1**：尽快交付可交互 UI 界面，敲定产品交互模式；
- **优先级 2**：尽快交付基于 `xray-core` 的可运行 Windows 程序供实测。

经对全量 39 张任务卡（10 张已 `done` 入 `main` + 24 张待办 P0 + 5 张 P1）执行 Kahn 拓扑排序验证（0 环、0 悬空引用），人类批准发布 v2.0 里程碑重排方案并直接启动 `PC-00b`。

## 2. 基线核正与 M0～M5 拓扑摘要
- **已完成基线（10 张 `done`，均已合入 `main 8954eb0`）**：`PC-00`、`PC-01`、`PC-02`（含 Go 绑定冻结）、`PC-17`、`PC-03`（H2/H4 转 `PC-11`，H3 转 `PC-10`）、`PC-04`、`PC-04b`、`PC-04c`、`PC-06`、`PC-07`（含 G6 节点出站宿主直连核心边界）。
- **已生效需求输入**：《需求确认基线 v1.3》（含 `REQ-33~36` 日志 6 项默认值：7 天 / 1 GiB / `expired` / `metadata` / 不做实时 tail / `127.0.0.1`，及 G-02~G-05 裁定）。
- **重排里程碑**：
  - **M0 基座收敛**：`PC-00b`（工程债清理、敏感输入零化、`protocol-parser` 解耦 `secure-store`、统一门禁 `tools/check-all`）。
  - **M1 交互定型（优先级 1）**：`PC-15a`（`ui/src/api/client.ts` 双通道底座 + 交互沙盒 Mock 驱动 + 原生模块化 CSS 变量设计系统 + SolidJS 核心桌面界面，零后端阻塞）。
  - **M2 Windows 可运行版（优先级 2）**：`PC-08a`（Windows `xray.exe v26.11.9` 监管 + 官方回环 gRPC 动态切换/流量）→ `PC-09`（`engine-scheduler` HTTP 204 探测与选路 + `SubscriptionFetcher`）→ `PC-14a`（无 Tauri 依赖的独立 `runtime-host` 用户态集成 + Windows 当前用户系统代理条件保存/恢复 + Tauri 真机联调）。
  - **M3 服务化与跨端控制面**：`PC-00c`（冻结 daemon/桥协同与 Web 无弹窗确认令牌 ADR）→ `PC-18a/18b`（`pcryoxy-daemon`）→ `PC-10`（Win SCM 服务 + 服务 SID 凭据迁移）/ `PC-19a/19b`（Linux systemd + 原生 TUN）/ `PC-20`（Web HTTP/WS 管理端）。
  - **M4 观测与在线更新**：`PC-21a/21b`（访问日志存储与观测查询）、`PC-12a/12b`（Geo 引擎与更新）、`PC-13a/13b`（核心升级与回退）、`PC-15b`（完整双通道与日志/更新页 + 性能基线测量）。
  - **M5 Android 真机独立轨与总签收**：`PC-05 → PC-11 → PC-12c`（独立并行，不阻塞桌面主线）→ `PC-16a/16b`（CI 量化回归门禁 + 三端硬件签收表）。

完整逐卡依赖、文件边界与两级验收标准（CI 自动化门禁 vs 硬件/特权签收）详见项目仓 `docs/02-任务卡总表.md`。
