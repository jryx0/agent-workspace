## 1. 目标

为 Windows 和 Linux daemon 提供本地结构化访问日志、节点/策略观测、延迟与速度统计、日志保留和启动清理、Web 查询与导出能力。

本卡不把以下能力写成无条件承诺：

- HTTPS 完整 URL 路径、查询参数、请求正文或请求头的默认记录；
- 仅凭 TUN 数据包 100% 反查原始进程；
- Windows TUN 或 Linux eBPF/cgroup 进程分流进入 P0；
- 远程公网日志管理；
- Android、iOS、鸿蒙 NEXT 的日志实现；
- AI 或第三方自动上报访问日志。

## 3. 记录范围

### 3.1 访问事件

至少包含：

```text
recordId
instanceId
time
platform
sourceApp（可空、平台能力不足时为 unknown）
targetDomain 或 SNI（域名级）
targetIp
port
protocol
policyGroup
selectedNode
routeReason
attempts（节点重试链）
dnsMs
connectMs
handshakeMs
ttfbMs
durationMs
uploadBytes
downloadBytes
averageUpKbps
averageDownKbps
status
errorCode
```

### 3.2 节点和策略事件

记录：

- 策略组目标改变；
- 最终节点改变；
- 故障转移和重试链；
- 节点健康检查结果；
- 节点 RTT、成功率、超时率；
- 运行时启动、停止、重启和恢复；
- 日志写入失败、容量超限和清理结果。

### 3.3 速度和延迟口径

速度只能记录真实代理流量或用户主动测速所得结果，不得把后台统计伪装成高级吞吐测速。

至少区分：

- DNS 延迟；
- TCP/UDP 建连耗时；
- TLS/代理握手耗时；
- 首字节耗时；
- 请求总耗时；
- 流持续时间；
- 上传/下载总字节；
- 流平均吞吐。

P1 高级吞吐测速仍需用户主动触发、限流和取消，沿用既有 P1 约束。

## 4. URL 与隐私边界

P0 的“访问网址”定义为域名级访问目标：`targetDomain`、SNI、目标 IP 和端口。

默认禁止记录：

- HTTPS URL path；
- query 参数；
- 请求正文；
- Cookie、Authorization 和其他请求头；
- 节点密码、订阅 URL、ticket、SecretRef；
- Xray 原始配置和完整错误文本。

明文 HTTP 的完整 URL、TLS 解密或 MITM 不属于本卡 P0，不得默认启用。访问日志属于本地敏感数据，不进入 AI、第三方遥测、崩溃上报或通用 SafeEvent。

通用 `SafeEvent` 继续只允许白名单安全事件；本卡新增 `AccessLogRecord` 是受鉴权的本地日志投影，不能作为对外或对 AI 的通用事件。

## 5. 日志存储

实现可滚动、可恢复的本地结构化日志。初始实现可以使用按日或按大小滚动的 UTF-8 JSONL；存储接口必须与查询实现解耦，不能把前端 DTO 当作磁盘格式。

必需配置：

```text
enabled
retentionDays
maxTotalBytes
rotatePolicy
startupCleanupMode
recordDetailLevel
redactQuery
```

`startupCleanupMode` 至少支持：

```text
none
expired
all_previous
```

建议默认：`expired`，并将默认值标为实现默认而非用户已经裁定的固定数值。`all_previous` 只删除本次启动前的日志，不删除本次启动新建文件。

日志目录和权限：

- Windows：服务身份可读写，ACL 不向普通用户组开放；具体目录由 PC-19 冻结。
- Linux：专属服务账户，目录至少 `0700`，日志文件至少 `0600`；具体目录由 PC-19 冻结。

日志写入不得阻塞代理数据面。使用有界异步队列；队列满、磁盘满或写入失败必须产生可查询的安全计数和状态，不得让核心无条件退出。关键生命周期事件与访问明细的丢失策略必须分别说明。

## 6. Web 查询范围

P0 支持本机 Web 查询：

```text
日志列表
按时间筛选
按应用筛选
按域名筛选
按策略组筛选
按节点筛选
按状态筛选
延迟和速度统计
流量统计
节点切换记录
日志清理结果
日志导出
```

默认只绑定 `127.0.0.1`。非回环监听沿用 REQ-30，必须启动时强制管理员 Token，缺 Token 拒绝启动；Token 不进入 URL、日志、响应、dist 或浏览器持久化。

P0 先实现历史查询和统计；实时日志 tail 可作为后续增量，不能为了实时展示扩大 SafeEvent 或取消有界队列约束。

## 7. 应用来源归属分级

### P0

- Windows/Linux 至少记录连接级来源字段；无法确认时明确写 `unknown`。
- 记录策略组、节点和流量指标不依赖进程识别。

### 后续增强

- Windows：WFP/连接-PID 映射和进程快照。
- Linux：UID、cgroup、socket owner、conntrack 或 eBPF 映射。
- PID 不作为稳定身份；进程路径默认不写入日志。
- 进程识别不足时不能猜测应用名称。

现有 P1 Windows TUN/进程分流卡仍保留，不因本卡把 TUN 或进程接管提前写成 P0。

## 8. 测试与验收

必须提供实际命令、退出码、环境和脱敏检查：

1. Windows 本地日志写入、滚动和查询；
2. Linux 本地日志写入、滚动和查询；
3. retentionDays 过期清理；
4. maxTotalBytes 容量清理；
5. `none`、`expired`、`all_previous` 启动清理；
6. 启动清理不删除本次启动日志；
7. 服务重启后可继续写入并能查询旧日志；
8. 断电/截断 JSONL 后恢复或跳过坏记录；
9. 磁盘满和队列满不阻断代理；
10. Web 默认回环绑定；
11. 非回环缺 Token 拒绝启动；
12. Token 不出现在 URL、日志、响应和前端持久化；
13. HTTP/WS/Tauri 查询结果使用同一 DTO 语义；
14. 域名级访问记录不含 query、正文、凭据和 ticket；
15. 策略组、最终节点、重试链、延迟、速度和流量字段与实际受控流量一致；
16. sourceApp 能确认时记录，不能确认时为 unknown，不伪造归属；
17. 访问日志不会进入 AI 或第三方上报；
18. 日志清理和导出权限受控；
19. Windows ACL 和 Linux 0600/0700 权限实测；
20. 读写并发和进程重启 race/故障路径测试。
