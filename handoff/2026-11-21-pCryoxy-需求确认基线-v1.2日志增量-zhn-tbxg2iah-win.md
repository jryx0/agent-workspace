## 1. 新增 P0 日志需求

### REQ-33：Windows/Linux 本地访问日志

Windows 和 Linux 运行形态必须提供本地结构化访问日志，至少可查询：

- 访问时间；
- 域名级访问目标、SNI、目标 IP 和端口；
- 使用的策略组；
- 最终选中的节点；
- 节点重试和故障转移链；
- DNS、连接、握手、首字节和总耗时；
- 上传/下载字节数；
- 真实流平均速度；
- 成功、失败和安全错误码；
- 可确认时的来源应用/进程标识。

无法确认来源应用时必须写明 `unknown`，不得根据目标域名或端口猜测应用。

### REQ-34：日志保留和启动清理

日志必须支持：

- 按天数保留；
- 按总容量限制；
- 按日期或大小滚动；
- 启动时不清理、只清理过期日志、删除上次启动以前日志三种策略；
- 服务重启后继续写入；
- 清理和写入结果可查询。

具体默认保存天数、默认总容量和目录由实现任务卡提出并在契约中冻结，不能在实现中静默决定并伪装为用户裁定。

### REQ-35：日志安全与隐私

日志默认采用域名级元数据，不默认记录 HTTPS 完整 URL path、query、请求正文、请求头、Cookie、Authorization、订阅 URL、节点凭据、ticket、SecretRef 或原始核心配置。

完整 URL、TLS 解密或 MITM 不属于本轮 P0。日志是本地敏感数据，不能进入 AI 上下文、第三方遥测或崩溃自动上报。

既有 `SafeEvent` 继续是通用安全事件白名单；访问日志使用独立的本地鉴权投影，不能通过扩大 SafeEvent 字段绕过脱敏边界。

### REQ-36：Web 日志查看

内置 Web 管理端必须支持本机查看和筛选 Windows/Linux 日志，并提供策略组、节点、延迟、速度、流量、状态和应用来源的查询维度；支持日志导出和受控清理。

默认仅绑定 `127.0.0.1`。非回环监听必须显式配置管理员 Token，缺 Token 拒绝启动。Token 不得出现在 URL、日志、响应、静态构建物或浏览器持久化中。

## 2. 对既有需求的明确修订

1. REQ-09 的“吞吐测速只能由用户主动触发”继续有效；REQ-33 的速度是实际代理流量的被动统计，不等同于后台主动吞吐测速。
2. REQ-23 的日志脱敏要求继续有效；REQ-35 将“域名级本地访问日志”定义为受控例外，不允许把原始 URL、秘密或完整配置写入日志。
3. REQ-28 的“流量查询”扩展为“访问日志查询、统计、导出和受控清理”，不改变已有 Web 鉴权和双通道 DTO 约束。
4. REQ-03、REQ-25 的 P0 平台范围保持 Windows、Android、Linux；本增量不把 iOS、鸿蒙 NEXT 或 macOS 提前纳入 P0。
5. Windows TUN/进程分流继续为既有 P1 后续能力。REQ-33 只要求可确认的来源字段和 `unknown` 降级，不把 TUN 层自动进程识别写成跨平台保证。
