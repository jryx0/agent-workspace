## 七、多设备同步机制（2026-11-12 09:53 人类提问，技能升 v0.3.0）

- **问题**：多台设备更新文件怎样同步？飞书文件已更新，其他设备怎样知道？
- **结论**：只有三种得知途径——①写入方登记索引版本戳（默认主渠道）；②读取方读前校验元数据/索引；③事件推送（仅飞书 `drive.file.edit_v1`，按 file_token 订阅、需文档管理权限与常驻接收进程，Webhook 或官方 SDK 长连接）。**百度网盘 MCP 无事件能力，只能轮询**。
- **关键限制**：飞书被人直接在线编辑而未经过任何 agent 时，索引不会自动知道；只能轮询飞书元数据或部署事件订阅，否则其他设备无从得知。不得承诺实时双向同步。
- **默认策略**（零常驻服务）：索引即公告板 + 写后登记 + 读前校验 + 会话开始刷新（只报告不自动下载）。
- **状态机**：clean / remote_newer / local_newer / conflict / copy_newer_than_origin / unknown；冲突停止交人类，不自动合并 Office/二进制；飞书副本新于原件时告警，回流需导出→覆盖原件→重算 sha256→更新索引→重建副本，每步人类确认。
- **写冲突预防**：乐观锁（上传前先读后端版本）、单 owner、批次锁。
- **启用门槛**：后台轮询或飞书事件订阅须人类批准单独建自动化；若要求「飞书一改各设备即时自动同步」属飞书升级为原件的架构迁移，须修订 rules.md 二-3，默认不启用。
- 已更新：审核报告第九节、技能 v0.3.0（新增第 7 节、索引版本戳字段，双副本 SHA256 一致）；未建任何自动化、未装依赖、未操作网盘/飞书。挂起任务快照同第四节，无变化。
