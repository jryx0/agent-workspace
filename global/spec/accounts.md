### 8. 多账号协同

> 各设备的实际账号目录与对应标识登记在 `env/agents.md` 账号登记表；技能层「个人版／企业版共存」结论见 `skills/official-doc/zhn-docs-kb/SKILL.md` 15.8。本节只管**协同调度层**（署名、认领、注入、凭据、部署授权），不重复三层资产清单。

- **① 定位**：账号是**定责标签 + 凭据／权限域**，**不是新的身份主键**，也不是防撞键。共享仓 `~/.agent-shared` 只有一个，**不按账号拆分**——拆开会破坏 〇⑤ 单一原件、三-1「只读最新一份 handoff」与三-2〔spec/memory-compaction.md〕 的 90 天归档；`handoff/`、`org.md`、`tmp/` 同样不按账号分目录。
- **② 账号标识由人类命名（规则）**：在 `env/agents.md` 的「账号登记表」登记，字段 `账号标识 | 平台/版本 | 主体 | 关联agent名 | 设备 | 注入状态 | 凭证边界 | 状态/启用日期`。**未登记的账号标识不得用于署名、认领、部署**；agent 不得自取、不得从目录名推断账号名。
- **② 标识格式（定义，人类 2026-11-12 12:24）**：三段式 `<账号主体>-<设备简称>-<OS段>`。① **账号主体**（第一段）由人类指定，表示「人＋账号类型」（如个人版、企业／团队版各取一个）；② **设备简称**（第二段）由人类指定并登记进 `memory/devices/_devices.md`；③ **OS 段**（第三段）按实际运行 agent 的操作系统取值，字母表由人类 12:24 指定：`w`＝Windows、`l`＝Linux（含 NAS 等 Linux 系）、`i`＝iOS／iPadOS、`a`＝Android、`m`＝macOS、`h`＝鸿蒙 HarmonyOS、`wl`＝WSL（Windows 内的 Linux 运行环境，单独取值；须人类登记后方可使用，且工作区仍只在 Windows 侧，见 四-1〔spec/toolchain.md〕）、`o`＝其他未列系统。
- **② 分隔与命名边界**：**段间以 `-` 分隔，段内一律禁止出现 `-`**；第三段可为 1–3 位小写字母（如 `wl`）。**不同 agent 软件不写进账号标识**——`workbuddy`／`trae` 等由定责键中独立的 `agent名@设备名` 前缀区分（③），同一账号标识下多个 agent 软件并存是正常用法；账号标识是凭据／权限域标签，不是身份主键，也不进防撞键。
- **② 当前取值与旧名（不写入规范）**：**当前正式标识与旧名映射只登记在 `env/agents.md`**（规范不写具体取值），**历史条目不追溯改写**。设备简称与 OS 段的权威来源是 `memory/devices/_devices.md`；跨设备换第二段、OS 变更换第三段，须先更新设备表再改标识。
- **②-补1 接入即提示生成标识（人类 2026-11-12 12:37 定义）**：新设备／新账号／新 agent **首次接入协同体系时，agent 须在第一个输出提示人类按三段式生成账号标识**，并给出候选串（第一段账号主体、第二段设备简称、第三段 OS 段），**同时询问「是否为虚机」**；人类确认前**不得自取、不得从目录名推断、不得用于署名／认领／部署**，并须同步登记 `env/agents.md` 与 `memory/devices/_devices.md`。已有登记标识直接沿用。该提示已按 〇⑦ ⑤ 写入平台全局指令二-L1／A 段（两处逐字同源，人类批准变更）。
- **②-补2 虚机标识与边界（人类 2026-11-12 12:37 定义）**：第三段＝**可选 `v` 前缀 + OS 字母**（`vw`＝Windows 虚机、`vl`＝Linux 虚机、`vm`＝macOS 虚机…），第三段放宽为 **1–3 位小写字母**；**`v` 仅在人类明确声明「这是虚机」时添加**，agent 不得自行探测 hypervisor、不得把容器／WSL／沙箱／未声明的云主机当作虚机。**虚机作为独立设备**：须在 `memory/devices/_devices.md` 单独登记设备名并分配**独立第二段设备简标**（例：宿主 `zhn-x-w`；Hyper-V 托管的 Windows 虚机登记简标 `y` → `zhn-y-vw`），**虚机与宿主凭据边界完全分开**，`config/` 由人类按 六节〔spec/secrets.md〕单独逐项分发，不得因同宿主机而复制（三-8 ⑥⑦⑨）。
- **③ 定责键（可选后缀）**：记忆行 `[@agent名 @设备名~<账号标识>#<会话标识> YYYY-MM-DD HH:mm UTC+8 内容]`；commit `… by <agent名>@<设备名>~<账号标识>`；项目代码 `Agent:` trailer 不变。**不同 agent 软件的区分就在 `agent名` 前缀**：同机同账号下 `workbuddy@zhn-tbxg2iah-win~zhn-x-w` 与 `trae@zhn-tbxg2iah-win~zhn-x-w` 靠前缀区分，账号标识相同不构成冲突。**历史条目不追溯改写**，无后缀一律视为该设备上的默认账号。
- **④ 防撞键不变**：任务认领与挂起防撞仍按「**项目 + 任务ID**」（三-4 / 三-5 ⑤）。账号**不进入防撞键**——否则同一张卡会被两个账号各认领一次。三-5 ⑤「无论认领者是否自己」跨账号同样成立：A 账号认领的卡，B 账号也不得开工；同为 `suspended` 的快照项对两个账号一律生效。
- **⑤ 注入按账号各配一次**：平台全局指令（〇① 1）须在每个账号下各配置一次，并各做一次 〇④ 首次注入验证；磁盘上 `~/.workbuddy/app/app-config.json` 只有一份机器级副本；**2026-11-12 已实测关闭该待验证项**（实测结论见 `env/agents.md` ②）。未注入账号的会话按 〇③ 停止写操作并上报人类。`user-<id>-*` 身份／记忆文件按账号隔离，**禁止跨账号复制**。
- **⑥ 并发资源细分与凭据共用边界**：同 agent 名多账号按三-5 ⑦ 跨会话并发同等处理——`tmp/<agent名>/<账号标识>/<会话标识>/`、worktree `.wt/<agent名>-<账号标识>-<任务>/`、自起服务在 agent 端口段内按账号登记实际端口；`~/.agent-tools/venvs/<agent名>/` **默认仍共用一份**（四-5 ②〔spec/toolchain.md〕 不按账号拆分，避免重复安装与版本漂移）。**凭据类（凭证、登录态、连接器授权）的共用范围限定为「同一台设备 + 同一个 agent 软件」**（人类 11:49／11:50 定义，即「同一 agent」的准确含义）：该范围内同一 agent 软件的多个平台账号**可共用**一份 `config/` 与机器级连接器授权，不单独分发；**跨设备、跨 agent 软件一律禁止**共用、复制或分发。身份／记忆目录仍按账号隔离（⑨）。`config/` 与 `venvs/` 是**设备级／agent 软件级**目录，同机已登记的多个 agent 名读取同一份物理文件属既有设备级用法，但不得据此把登录态或连接器授权搬到另一台设备或另一软件。
- **⑦ 凭据边界**：`config/` 是**设备级**凭证（六）〔spec/secrets.md〕，共用范围见 ⑥。
  - **允许**：同一台设备、同一个 agent 软件下的多个平台账号共用一份 `config/`、私钥／token 与机器级连接器授权；人类 2026-11-12 11:44 已裁决共用、不另做隔离（裁决细节见 `memory/archive/2026-11-rules-v2.7-moved.md`）。
  - **禁止**：把 `config/`、私钥／token、登录态或连接器授权**复制到另一台设备**或**搬给另一个 agent 软件**；新设备仍按 六节〔spec/secrets.md〕由人类手动逐项分发；把平台登录态写进共享仓。
  - **附加条件**：若同一设备同一 agent 软件下出现**不同主体**账号（个人／企业分属不同法人），是否仍共用须人类单独裁决，不得按「同设备」自动推定（判断方法见技能 15.8）。
  - `keys-checklist.md` 标注「适用设备 + agent 软件」；自检第 1 步（八-1）按当前设备核对适用项，不因另一账号缺项而误报。
- **⑧ 部署授权**：三-7〔spec/deploy.md〕 的授权**不可跨账号推定**——「人类当次点名授权」须写明针对哪个账号；部署留痕须含账号标识（三-7 ⑤〔spec/deploy.md〕）。
- **⑨ 禁止**：按账号拆共享仓或 handoff 目录；把账号写进防撞键；agent 自判账号；**跨设备／跨 agent 软件复制 `config/`、登录态或连接器授权**；**跨账号复制 `user-<id>-*` 身份／记忆目录**（身份层隔离不因 ⑥⑦ 放宽）；把账号级记忆写进 Git（最小红线集①）。
- **⑩ 与技能层分工**：技能 15.8 的三层资产表（技能＝机器级／身份记忆＝账号级／连接器凭证＝机器级）作为引用附件，本节不重复也不覆盖；两者冲突时以本节（协同规范）为准，技能文档按第十节上报人类订正。
