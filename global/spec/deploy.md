## S3.7 Deployment Authority

> 「部署」指 `wrangler deploy`、云平台发布、数据库迁移、容器/服务启停升级等一切改变线上状态的动作；**`git push` 与本地构建不等于部署**。

- **S3.7a 权限收口**：默认仅**审核方 `workbuddy`** 具备部署判断权。其他 Agent（含编码执行者）一律不得部署，除非人类在**当次任务明确点名授权该 Agent 与具体账号**（`[spec/accounts.md#S3.8h]`）；授权不可跨任务、跨会话、跨账号推定。
- **S3.7b 审核后处置**：复审通过并合并收官后，`workbuddy` 自行判断是否直接部署——**全部满足 `S3.7c` 即直接部署，不必逐次询问**；任一项不确定即停并通知人类，说明卡点、给可复制命令与线上自检项。禁止猜测、试部署。
- **S3.7c 「能确定」四项前置（缺一不可）**：
  1. 改动范围已在卡面/审核记录列全且仅限已合并代码/生成物；**不涉及** DB migration、表结构、secret/环境变量、账号/域名/路由/绑定/计费变更；
  2. 部署命令来自项目 `package.json` scripts 或已登记入口（项目级 CLI 用项目本地 `node_modules`，`[spec/toolchain.md#S4.4g]`），本机可用、凭据有效且无需交互登录；
  3. 部署目标明确，且人类当前未操作该服务（`R3`）；
  4. 具备可执行的部署后线上自检（HTTP/哈希/关键特征）与明确回滚方案。
- **S3.7d 必须交人类情形（任一命中即停）**：涉及 migration/secret/配置/凭据/域名变更；命令或登录态不可验证；首次或路径不明的部署；生产事故恢复需拍板；部署链路网络异常；其他 Agent 请求部署；人类正操作同一服务。
- **S3.7e 部署后留痕与异常处理**：部署后立即执行线上自检，并在 `memory/projects/<项目>.md` 追加记录（时间、基线 commit、部署者及账号标识、自检结果）。自检失败**立即上报人类并给回滚建议，禁止反复重试**；不得替他人顺手发版。
- **S3.7f 状态同步**：记忆须写明当前线上版本与基线是否一致；交由人类部署时明确标注「待人类部署」，防止后续会话误判线上已更新。
