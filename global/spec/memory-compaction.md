### 2. 记忆压缩机制 (Compaction)
- **append-only 的唯一例外**：记忆压缩是**唯一允许改写记忆文件（截断/重组）的机制**，且仅限主设备在压缩窗口内执行。窗口外任何改写记忆文件的行为均违规。
- **周期**：每月 1 次（人类用户发起，建议固定在每月第一个周末）。**保留期统一为 90 天**（记忆条目与交接文档一致），压缩流程中**一步同时处理 `memory/` 与 `handoff/` 的归档**，避免两套周期漏处理。人类临时指定的压缩不受本条限制，见下方「临时压缩」。
- **执行者**：由人类指定的一台**主设备**（建议：主力 Windows 机）上的任一 agent 执行，同一周期内只允许这一台设备执行压缩。
- **锁文件机制**：压缩前先创建 `memory/.compact-lock`（内容：设备名 + ISO 时间戳）并**单独 commit + push**。其他设备自检时发现锁即**暂停写入记忆**，直至锁被删除。压缩完成后，删锁与压缩内容在同一个 commit 中一并推送。
- **流程**（严格按序）：
  1. 按 五-1「提交前同步」规则确保最新（有他人未提交改动且本地落后时不得 pull，报告人类并中止压缩）；
  2. 创建并推送 `memory/.compact-lock`（含设备名+时间戳），从 push 锁起进入压缩窗口，**全流程原则上不超过 30 分钟**；
  3. 读取 `org.md` 及各项目记忆全量内容；
  4. 将超过 90 天的条目提炼为摘要，写入 `memory/archive/YYYY-MM.md`（按主题分节，保留决策结论与关键链接，丢弃过程细节）；同时将超过 90 天的 handoff 移入 `handoff/archive/YYYY-MM/`；**挂起项归档保护**：压缩前对照最新 handoff 的「挂起任务」快照，把仍未解挂且超过 90 天的项逐条写入当月归档摘要（项目 / 任务ID / 挂起原因 / 解挂前置 / 裁决出处），并在压缩后生成的最新一份 handoff 中续记，禁止随旧 handoff 进入只读归档而丢失；
  5. 将 `org.md` 截断为：压缩后的最新摘要 + 保留期内原始条目；同 commit 删除 `.compact-lock`；
  6. 立即 push，commit message 格式：`memory: compact 2026-11 by <agent>@<设备>`；
  7. **验证备份库**：push 后在临时目录对 GitHub backup 远端执行一次 `git clone --depth 1`，确认镜像可用；
  8. **维护各项目 worktree**：对本机 `~/source/` 下各项目执行 `git worktree prune`，并清理已合并的 `agent/*` 本地分支（见 三-6〔spec/worktree.md〕）。
- **临时压缩（人类指定窗口，v2.8 起）**：人类可在当次会话中临时指定一次压缩，该次**不受 90 天保留期与每月 1 次的限制**。
  - **授权**：人类须明确给出范围（哪些记忆文件，如某项目记忆或 `org.md`）与截止点（截止时间或截止条目）；授权仅对当次有效，不得跨任务／跨会话推定，范围或截止点不明确时先问人类。
  - **流程**：照上方流程第 1～3、5～7 步执行（主设备、锁文件、30 分钟窗口、删锁同提交、push 后验证备份库），第 4 步的"超过 90 天的条目"换成"人类指定范围内截止点之前的条目"；handoff 只在人类点名时才归档，第 8 步可跳过。
  - **摘要**：写入新建的 `memory/archive/YYYY-MM-DD-<范围>.md`，不改既有归档；摘要须逐条保留截止点前仍未结的事项（doing/blocked 卡、未解挂的挂起项、待人类裁定项），写明项目／任务ID／当前状态／出处，并保留决策结论与关键链接。被截断的文件开头写一行指针，注明摘要文件路径与截止点。
  - **留痕**：commit message 仍用 `memory: compact YYYY-MM by <agent>@<设备>`，正文写明人类指定的范围、截止点与授权时间；同时在被压缩文件的末尾追加一行登记。
- **归档只读**：`memory/archive/` 与 `handoff/archive/` 下的文件**一经写入即为只读**，后续周期不得修改既有归档，新月份/新周期新建文件。
