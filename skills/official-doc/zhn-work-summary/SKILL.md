# zhn-work-summary — 日常工作记录与月/季/年总结

## 1. 这套东西解决什么

日常随手记一句，月底不用从零回忆；季度末不用把三个月的 Excel 翻一遍。**记录层只负责"发生了什么"，总结层只负责"归纳与成文"**，两层分离，避免记录时被迫写成公文。

## 2. 目录与文件约定

**根目录**：`~/.agent-docs/工作/`（重要文档同步区，不进 Git；跨设备靠同步工具）

```
~/.agent-docs/工作/
├── 记录/
│   └── YYYY-MM.md          ← 日常记录，一个月一个文件，append-only
├── 261117｜总结｜2026年二季度工作情况总结.docx    ← 季度总结（官方表格口径）
├── 中建三局总部员工季度工作情况总结_2026年三季度.xlsx  ← 历史原件
└── 2612xx｜总结｜2026年度工作总结.docx          ← 年度总结（叙述式）
```

- **记录文件命名**：`记录/YYYY-MM.md`（如 `记录/2026-11.md`）。固定格式，不加 `｜类型｜`，因为它是滚动工作文件而非归档文档。
- **总结文件命名**：按 `zhn-docs-std` 的 `YYMMDD｜类型｜主题.ext`。类型段用 `总结`。
- 归档到别处时遵守 `zhn-docs-std`；本技能只负责内容。

## 3. 记录层：怎么写日常记录

### 3.1 触发

用户说「记一下」「今天做了…」「随手记」或直接粘贴一段工作内容。

### 3.2 写法

1. 定位当月文件 `记录/YYYY-MM.md`，**不存在就建**（用模板见 §7）。
2. 按日期分节，**append-only**，不重排、不改历史行。
3. 每条记录**只写事实**，不追求文采。允许以下任意粒度：
   - 一句话：「上午跟运维核了 17 号打印机碳粉，实际 19%，系统显示 28%，是断采。」
   - 一串要点：「- 视频会议设备巡检 3 间\n- 处理 OA 权限异常 2 起」
   - 直接贴会议纪要/邮件片段。
4. **主动补三个字段**（用户没写就问，一句话问完即可，不追问）：
   - **对象**：涉及哪个单位/系统/设备
   - **量**：次数、台数、金额、家数（**这是总结里最有说服力的东西**）
   - **结果**：完成/在推进/卡在哪

### 3.3 记录时不做的事

- 不替用户编造成果、不夸大、不写「取得了显著成效」这类空话。
- 不把记录写成总结——记录是原料，总结是成品，混在一起两边都做不好。
- 不擅自删除用户写的口语化表述（那是回忆线索）。

## 4. 总结层：月 → 季 → 年

### 4.1 三层关系

| 层 | 输入 | 输出 | 篇幅 |
|---|---|---|---|
| **月度** | 当月 `记录/YYYY-MM.md` | 纯文本 + 条目，`记录/总结/YYYY-MM-月度小结.md` | 600–1200 字 |
| **季度** | 3 个月的月度小结（缺则回读原始记录） | 套官方表格（见 §5） | 表格 + 亮点 800 字 + 短板 250 字 |
| **年度** | 4 个季度总结 + 年度目标责任书 | 叙述式（见 §6） | 2000–3000 字 |

**递进原则**：上层只引用下层结论，不重新翻原始记录（除非下层缺失）。每月小结写完就冻结，季度总结不回头改月度小结。

### 4.2 归纳口径：先归类，再成文

把当月事实**先归入工作要素**（这套分类来自真实考核表，稳定复用）：

| 工作要素 | 典型内容 |
|---|---|
| 年度目标责任书工作 | 信创（CentOS 下线、资产填报、非信创采购管控）、软件正版化、巡视整改"回头看"迎检 |
| IT 基础设施工作 | 基础设施采购、网络改造、IP 地址治理、机房 |
| 运维管理工作 | 视频会议保障、机房巡检、统建系统（OA/门户/三局通）日常运维 |
| 巡查工作 | 巡查整改督导、问题销号 |
| 系统开发工作 | 穿透式巡查监督系统等自建系统 |
| 数字指标统计工作 | 数字业务指标统计、报表开发、采集优化 |

归不进上述任何一类的，单列「其他新增重点工作」——**不要为了凑分类硬塞**。

### 4.3 写作风格（按真实样本提炼，务必遵守）

1. **开头定调**：`<时间段>，根据集团工作部署 / 立足<岗位>职责，组织/推进<主干事项>。`
2. **并列用「一是…二是…三是…」**，不用 markdown 列表（公文不用项目符号）。
3. **动词开头**，每句一个动作：组织、统筹、牵头、协调、督促、指导、配合、推进、落地、闭环、核验、摸排。
4. **量化优先**：能写数字绝不写「多次」「若干」。样本里的「15 次设备维修」「5 万元」「1204 张报表」就是标准。
5. **结果句收尾**：每段最后落到「保障了…」「推动…见底清零」「为…奠定基础」。
6. **不用第一人称**「我」，用无主语或「组织」「配合」；不用「我觉得」「可能」。
7. 涉及文件写全称加书名号并注明发文时间与发文单位：`印发《关于规范软件资产管理的通知》（中建三局数字产业事业部2026年9月22日）`。

## 5. 季度总结：官方表格口径

### 5.1 表格结构（固定，不要改列）

| 列 | 说明 |
|---|---|
| 工作要素 | 一级分类（§4.2 六类 + 其他） |
| 工作内容或步骤 | 二级分类 + 编号条目，如 `1. CentOS操作系统下线组织推进` |
| 具体完成（进展）情况 | 该条目的详细叙述，**单条 70–400 字** |

表头信息：`部门 / 姓名 / 岗位 / 考核期：YYYY年M月至YYYY年M月`。

### 5.2 表尾两个固定段落

- **考核期内最具代表性的两项亮点工作以及其他重大事项及工作成效**
  - 先写 `季度重点工作成效总结`：`<X>季度，立足<岗位>职责，扎实推进…等各项工作，圆满完成季度工作任务，核心工作成效亮点如下：`
  - 然后 `一是…。二是…。` 每项 300–400 字，**必须是"做法+机制+成效"三段式**，不是罗列事项。
- **考核期内最不满意的一项工作 → 工作不足与短板分析**
  - 200–250 字。**先承认整体完成，再讲具体短板**，短板要指向可改进的机制（如"过渡期风险预判不够充分""技术帮扶精细化程度不足"），不写"能力有待提高"这种无法验证的话。

### 5.3 输出

- `.xlsx`（官方填报）与 `.docx`（存档/阅读）两条都出，内容一致。
- 生成 xlsx 时用 `workbuddy-sheetagent`；生成 docx 时用 `workbuddy-docx`。
- 表尾如为 AI 生成，**保留** `（注：部分内容可能由 AI 生成）` 一行，不擅自删。

## 6. 年度总结：叙述式

与季度表格不同，年度用**连续叙述 +（一）（二）（三）分条**（见历史样本 `2021年度工作总结`）：

```
YYYY年度工作总结

YYYY年，按照工作职责和目标责任状的要求，主要工作如下：
（一）<动词短语概括>。<具体做法，含量化>。
（二）…
…
YYYY年，主要承担<主线>方面的工作，<不足>。
YYYY年，将根据工作安排重点推进以下工作：一是…二是…三是…
```

要点：**开局一句总述、分条写事、结尾自评不足 + 下年计划**。年度总结必须包含「下一年计划」，季度总结不需要。

## 7. 记录文件模板

```markdown
# YYYY年M月工作记录

> 部门：数字产业事业部 ｜ 姓名：<姓名> ｜ 岗位：IT基础设施管理岗
> 用法：随手记，一句话一件事也行，不用讲究格式。月底按「工作要素 → 工作内容或步骤 → 具体完成情况」三层归纳成月度总结。

## MM-DD 周X

-

## 待办 / 跟进

-
```

## 8. 执行清单

**记一条**：定位/建当月文件 → 追加到当日节 → 缺量/结果则一句话补问 → 完。

**写月度**：读当月记录 → 按 §4.2 归类 → 按 §4.3 成文 → 落 `记录/总结/YYYY-MM-月度小结.md` → 把当月未闭环事项转到 `## 待办 / 跟进`。

**写季度**：确认考核期起止 → 读 3 个月小结（缺则回读原始记录）→ 按 §5 填表 → 出 xlsx + docx → 提示用户核对数据。

**写年度**：确认年度 → 读 4 个季度总结 + 年度目标责任书 → 按 §6 成文 → 出 docx。

## 9. 边界

- **不编造事实**。记录里没有的，宁可留空让用户补，不推测。
- **不改历史记录**。发现记错，追加一条更正，不回头改。
- 用户口述内容若涉及未公开的敏感经营数据，只落本地 `~/.agent-docs`，不上传、不外发。
- 本技能只产出文本与文档，不代用户提交任何考核系统。
