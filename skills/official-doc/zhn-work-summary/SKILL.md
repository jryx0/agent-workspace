# zhn-work-summary — 日常工作记录与月/季/年总结

## 1. 这套东西解决什么

日常随手记一句，月底不用从零回忆；季度末不用把三个月的表格翻一遍。

**记录层只负责「发生了什么」，总结层只负责「归纳与成文」**——两层分离，避免记录时被迫写成公文。

固定产出：**月小结 → 季度总结 → 年度总结**，每层向上一层的输入就是下一层的成品，不重读原始记录。

## 2. 目录与文件约定

**根目录**：`~/.agent-docs/工作/`（重要文档同步区，不进 Git）

```
~/.agent-docs/工作/
├── 记录/
│   ├── 2026-11.md                          ← 日常记录，一个月一个文件，append-only
│   └── 总结/
│       └── YYMMDD｜总结｜YYYY-MM月度小结.xlsx   ← 月小结（可选，季末可补）
└── 261117｜总结｜2026年一至三季度工作情况汇总.md   ← 唯一留存的汇总版（最终版）
```

- **记录文件**：`记录/YYYY-MM.md`。固定格式，不带 `｜类型｜`——它是滚动工作文件，不是归档文档。
- **总结文件**：按 `zhn-docs-std` 的 `YYMMDD｜类型｜主题.xlsx`，类型段用 `总结`；月、季、年总结的交付格式**只用 `.xlsx`**。不另生成 `.docx`、`.md` 总结文件。日常工作记录仍按月追加到 `记录/YYYY-MM.md`，该日志不是总结交付物。
- 官方 docx / xlsx 原件（二季度 docx、三季度 xlsx）**不再随目录留存**，人类 2026-11-17 12:11 已确认删除，备份在 `~/.agent-tools/backups/agent-docs-工作-20261117/`；需要回查原表格时从备份取。

## 3. 记录层：怎么写日常记录

### 3.1 触发

用户说「记一下」「今天做了…」「随手记」，或直接粘贴一段工作内容、会议纪要、截图文字。

### 3.2 最小条目（用户按这个给就行，缺项留空）

```
【日期】2026-11-17
【工作类型】信创 / 软件正版化 / 巡视整改 / IT基础设施 / 运维 / 巡查 / 系统开发 / 数据统计 / 其他
【做了什么】一句话说清动作和对象
【关键事实/数据】数量、金额、次数、日期、节点（有则填，无则留空，禁止编造）
【结果/成效】完成情况、保障了什么、形成什么机制
【来源】截图/会议/通知文号（可选）
```

用户只写一句话也完全可以，agent 负责把它落到上面六项里。

### 3.3 落盘规则

1. 定位当月文件 `记录/YYYY-MM.md`，**不存在就建**（模板见 §7）。
2. 按日期分节，**append-only**，不重排、不改历史行。发现记错，追加一条更正。
3. **主动补三字段**（用户没写就问，一句话问完，不追问）：
   - **对象**：涉及哪个单位/系统/设备
   - **量**：次数、台数、金额、家数 ← **这是总结里最有说服力的东西，也是唯一不能事后编的**
   - **结果**：完成／在推进／卡在哪
4. 允许的口语粒度：「上午跟运维核了 17 号打印机碳粉，实际 19%，系统显示 28%，是断采。」原样保留，那是回忆线索。

### 3.4 记录时不做的事

- **不替用户编造成果**、不夸大、不写「取得了显著成效」这类空话。
- **不把记录写成总结**——记录是原料，总结是成品，混在一起两边都做不好。
- 不擅自删用户的口语化表述。

## 4. 总结层：月 → 季 → 年

### 4.1 三层关系

| 层 | 输入 | 输出 | 篇幅 |
|---|---|---|---|
| **月度** | 当月 `记录/YYYY-MM.md` | `记录/总结/YYMMDD｜总结｜YYYY-MM月度小结.xlsx` | 600–1200 字 | |
| **季度** | 3 个月小结（缺则回读原始记录） | 四列表格 + 两段亮点 + 短板段 | 表格 + 亮点各 300–400 字 + 短板 200–250 字 |
| **年度** | 4 个季度总结 + 年度目标责任书 | 叙述式 | 2000–3000 字 |

**递进原则**：上层只引用下层结论，不重新翻原始记录（除非下层缺失）。月小结写完即冻结，季度总结不回头改月小结。

**年度去重**：同一项工作跨季只保留**最新进展**，累计量可相加（如维修次数），但不要四个季度各列一遍。

### 4.2 归类口径：两级分类（关键修正）

**一级「工作要素」只有 6 类 + 兜底**，这是真实考核表的固定口径，**不要自造**：

| 一级工作要素 | 二级分类（举实际出现过的） |
|---|---|
| **年度目标责任书工作** | 信创工作（CentOS 下线、资产填报、非信创采购管控）、软件正版化工作、巡视整改「回头看」迎检、设计类软件集采、WPS 推广、OA/门户/三局通运维、数字业务责任状、数字业务宣传册、月度指标统计、重大会议保障、基础设施巡检 |
| **IT 基础设施工作** | 基础设施采购与网络改造（打印机采购、IP 地址改造、IPv6 升级） |
| **运维管理工作** | 日常运维保障（视频会议、机房、统建信息系统） |
| **巡查工作** | 巡查整改督导（数字公司、信科公司问题销号） |
| **系统开发工作** | 穿透式巡查监督系统、督办中心业务中台 |
| **数字指标统计工作** | 数字业务指标统计、报表开发与采集优化、财商系统自动取数 |
| *（兜底）其他新增重点工作* | 配合审计、主数据管理、智能建筑项目专项配合、专项调研 |

> **常见错误（务必避免）**：把所有条目一律塞进「年度目标责任书工作」——这样一级要素就失去区分度，看不出岗位职责结构。**先判一级，再判二级**。

### 4.3 写作风格（从真实样本提炼，务必遵守）

1. **开头定调**：`<时间段>，根据集团工作部署 / 立足<岗位>职责，组织/推进<主干事项>。`
2. **并列用「一是…二是…三是…」**，不用 markdown 列表（公文不用项目符号）。
3. **动词领起**：组织、牵头、统筹、协调、督促、指导、配合、推进、落实、督导、推动、编制、完成、核验、摸排、闭环。避免口语和网络词。
4. **量化优先**：能写数字绝不写「多次」「若干」。样本里的「15 次设备维修」「5 万元」「1204 张报表」「16 场会议」就是标准。
5. **结果句收尾**：每段落到「保障了…」「推动…见底清零」「为…奠定基础」「由分散填报向自动归集转变」「形成闭环」「建立长效管控体系」。
6. **不用第一人称**「我」；不用「我觉得」「可能」「大概率」。
7. 涉及文件写全称 + 书名号 + 发文时间与单位：`印发《关于规范软件资产管理的通知》（中建三局数字产业事业部2026年9月22日）`。
8. **去 AI 味**：少用排比堆砌和华丽辞藻；**不虚构成效**；不确定处留占位，不硬写。

## 5. 季度总结：官方表格口径

### 5.1 表格结构（**四列**，与官方 xlsx 一致）

| 列 | 说明 | 合并规则 |
|---|---|---|
| **A 工作要素** | 一级分类（§4.2 六类 + 其他） | 同要素**跨行纵向合并** |
| **B 二级分类** | 如「信创工作」「软件正版化工作」「基础设施采购与网络改造」 | 同二级**跨行纵向合并** |
| **C 工作内容或步骤** | 一句短的动宾概括句，**带序号**（`1.` `2.` `3.`），**不展开** | — |
| **D 具体完成（进展）情况** | 用「一是、二是」分层展开事实、数据与成效，**单条 70–400 字** | — |

> **修正说明**：早前版本把 A、B 合成一列「工作要素」，导致一级要素失去区分度。官方 xlsx 实测为 `A4:B4` 表头合并、`A5:A8`/`B5:B6` 等纵向合并——**必须四列**。
> **序号**：`C 列` 带序号是官方原件做法（`1. CentOS操作系统下线组织推进`），保留；序号在二级分类内重新从 1 起。

表头信息：`部门 ｜ 姓名 ｜ 岗位 ｜ 考核期：YYYY年M月至YYYY年M月`。

### 5.2 表尾两个固定段落

**（1）考核期内最具代表性的两项亮点工作以及其他重大事项及工作成效**

- 先写引导句：`<X>季度，立足<岗位>职责，扎实推进…等各项工作，圆满完成季度工作任务，核心工作成效亮点如下：`
- 然后 `**一是**<八字对仗小标题>。…` / `**二是**<八字对仗小标题>。…`
- 每段 **300–400 字**，两段**篇幅均衡、句式对仗**。
- 必须是「**做法 + 机制 + 成效**」三段式，不是罗列事项。小标题例：`规范软件资产管理，构建正版化长效管控体系`。
- **只选两项**，其余工作不进亮点（否则亮点不亮）。

**（2）考核期内最不满意的一项工作 → 工作不足与短板分析**

- **每个季度都必须有这一段，不得空缺**。历史汇总版里出现过「在线系统截图中未见独立板块，无对应记录」这种写法，属于**错误**——官方表格每季都有，缺了要补。
- 200–250 字。
- **先承认整体完成，再讲具体短板**，短板要指向**可改进的机制**（如「过渡期风险预判不够充分」「技术帮扶精细化程度不足」「差异化网络适配场景预判不够全面」），不写「能力有待提高」这种无法验证的话。
- 必须带**改进方向**（下季度/四季度将…）。

> **已确认的真实口径（2026-11-17 人类口述，勿再记为缺失）**：
> - 二季度：`二季度各项重点工作均按期完成，但工作中仍存在一定短板与不足。在网络IP改造及IPv6升级工作中，整体方案编制、现状调研工作推进高效，但针对各单位差异化网络适配场景的预判不够全面，对部分老旧设备IPv6改造的兼容性风险预判不足，方案细节仍有优化空间。`
> - 三季度：CentOS 下线替代推进中部分单位进度不均衡、个别单位适配验证周期长，四季度加强信创力度督促按时完成替代。

### 5.3 输出格式：**只出 xlsx**

- **一律只生成 `.xlsx`**（正式交付版），不另生成 `.docx` 或 `.md` 总结文件。
- 生成 xlsx 用 `workbuddy-sheetagent`；**禁止**调 `workbuddy-docx` / `doc-formatter` / `doc-converter` 产 docx。
- 表格样式沿用官方口径：表头 `部门 ｜ 姓名 ｜ 岗位 ｜ 考核期`；主表四列（A 工作要素、B 二级分类、C 工作内容或步骤、D 具体完成情况），A/B 列**纵向合并**；`C` 列带序号；`D` 列自动换行、列宽 `A=18 / B=22 / C=34 / D=80`、`wrap_text=True`、`vertical=top`。
- 表尾两个固定段落在 xlsx 里写作**合并单元格的整段文本**（`A:D` 合并），段前空一行，段标题加粗。
- 表尾如为 AI 生成，**保留** `（注：部分内容由 AI 生成 / 豆包 AI 生成）` 一行，不擅自删。
- 人类 2026-11-17 12:00 明确：**每次只生成 xlsx 文件，不生成 docx**。此条优先于任何历史版本的三格式约定。

## 6. 年度总结：叙述式

与季度表格不同，年度用**连续叙述 +（一）（二）（三）分条**（见历史样本 `2021年度工作总结`）：

```
YYYY年度工作总结

YYYY年，按照工作职责和目标责任状的要求，主要工作如下：
（一）<动词短语概括>。<具体做法，含量化>。
（二）…
…

YYYY年，主要承担<主线>方面的工作，<不足>。
YYYY年，将根据工作安排重点推进以下工作：一是…二是…三是…
```

要点：**开局一句总述、分条写事、结尾自评不足 + 下年计划**。年度总结**必须包含下一年度工作打算**，季度总结不需要。

## 8. 执行清单

**记一条**：定位/建当月文件 → 追加到当日节 → 缺量/结果则一句话补问 → 完。

**写月度**：读当月记录 → 按 §4.2 判两级分类 → 按 §4.3 成文 → 生成 `记录/总结/YYMMDD｜总结｜YYYY-MM月度小结.xlsx` → 未闭环事项转当月记录 `## 待办 / 跟进`。

**写季度**：确认考核期起止 → 读 3 个月小结（缺则回读原始记录）→ 按 §5 填四列表 → **只出 xlsx** → 提示用户核对数据。

**写年度**：确认年度 → 读 4 个季度 xlsx + 年度目标责任书 → 跨季去重 → 按 §6 成文 → **只出 xlsx**（叙述式段落按合并单元格整段排）。

## 9. 交付前自检（逐条过）

- [ ] 一级工作要素**没有全部塞进「年度目标责任书工作」**，六类有区分
- [ ] 表格是**四列**，A/B 列纵向合并已做
- [ ] C 列是短动宾句、带序号、未展开
- [ ] D 列每条 70–400 字，用「一是二是」，末句落到成效
- [ ] **所有数字都有出处**（来自记录或用户口述），无一处编造
- [ ] 用户没给的数字，统一用 `＿`（全角下划线）占位，未用 0 或估计值
- [ ] 两项亮点各 300–400 字、篇幅相当、小标题对仗
- [ ] 「最不满意的一项」写了具体机制短板 + 改进方向，无空话
- [ ] **只出了 xlsx**，没有生成 docx
- [ ] 文件名符合 `zhn-docs-std`，AI 生成标注行保留
- [ ] 与上季度已交付版本比对：**新增事项是否遗漏、删除事项是否有依据**

## 10. 与豆包版技能的差异说明

本技能 v2.1.0 在豆包 `daily-to-quarterly-review` 基础上融合，**保留**其输入六字段模板、去 AI 味、下划线占位不编造、可直接复制的系统提示词；**修正**以下 6 处：

| # | 豆包版 | 本版 | 原因 |
|---|---|---|---|
| 1 | 只有季度+年度 | 增加**记录层**（`记录/YYYY-MM.md` append-only）与**月度层** | 人类的实际工作流是「日常随手记→月度→季度→年度」，记录层不落盘，季末仍要从零回忆 |
| 2 | 一级要素列为「信创/软件正版化/巡视整改/IT基础设施/运维/巡查/系统开发/数据统计」8 类平铺 | 一级**只 6 类**（年度目标责任书/IT基础设施/运维管理/巡查/系统开发/数字指标统计）+ 兜底，信创等降为**二级** | 真实考核表的一级就是 6 类；平铺会导致「年度目标责任书工作」被架空，一级失去区分度 |
| 3 | 主表三列（工作要素｜工作内容或步骤｜具体完成情况） | **四列**（工作要素｜二级分类｜工作内容或步骤｜具体完成情况） | 官方 xlsx 实测为四列 + 纵向合并；三列会丢掉二级分类层 |
| 4 | 「工作内容或步骤」**不编 1/2/3** | **带序号**，二级内从 1 起 | 官方原件就是 `1. CentOS操作系统下线组织推进`；与真实表格保持一致 |
| 5 | 无版本号、无自检清单、无命名衔接 | 补 `version`、§9 交付前自检 11 条、§2 命名与 `zhn-docs-std` 衔接 | 缺验收门禁容易漏「数据无出处」「版本不一致」这类硬伤 |
| 6 | 三格式同步（docx + xlsx + md） | **只出 xlsx**，不出 docx | 人类 2026-11-17 12:00 明确要求；docx 版式易漂移、复核成本高，xlsx 才是考核表本体 |

## 11. 边界

- **不编造事实**。记录里没有的，宁可留 `＿` 占位让用户补，不推测、不估计。
- **不改历史记录**。发现记错，追加一条更正，不回头改。
- 用户口述若涉及未公开的敏感经营数据，只落本地 `~/.agent-docs`，不上传、不外发。
- 本技能只产出文本与文档，**不代用户提交任何考核系统**。
