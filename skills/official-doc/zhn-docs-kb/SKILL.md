# zhn-docs-kb — 多 Agent 协同共享文档知识库

## 0. 状态与范围（先读这段）

- 依据：`docs://技术资料/261112｜文档｜飞书百度网盘混合存储方案审核.md`（含 09:45、09:53 补充修订）。上位约束为 `rules.md` v2.0，冲突时以上位规范为准。
- **同步范围仅两个目录**（人类 2026-11-12 指定）：
  - `~/.agent-shared`：只走 Git 双远端，**不上网盘/飞书**（含密钥与记忆，防泄露与双活）。
  - `~/.agent-docs`：本机为原件；百度网盘为备份/交付副本，飞书为可选预览副本。
- **内容范围**：多 Agent 工作产出文档 + 人类指定文档。超大视频与大型二进制**不纳入**，由人类自行备份。
- **外部后端未实测**：上传速度、限流、授权目录范围等均为 TBD（第 12 节）。实测前仅允许本地分层判断、命名、索引设计与只读检索；不自动上传、不自动生成分享链接。

## 1. 分层与 URI

| 层 | 位置 | URI | 角色 | 原件归属 |
|---|---|---|---|---|
| 共享仓层 | `~/.agent-shared` | Git 路径 | 规范/技能/记忆/配置，双远端同步 | 原件 |
| 活跃文档层 | `~/.agent-docs` | `docs://<相对路径>` | Agent 产出文档与人类指定文档 | **原件唯一** |
| 备份交付层 | 百度网盘（官方 MCP） | `pan://<相对路径>` | 备份、批量文件夹上传、对外交付 | **仅副本** |
| 在线协作层（可选） | 飞书云空间 | `feishu://<file_token 或路径>` | 在线预览、多人协作 | **仅副本** |
| 索引层 | `~/.agent-docs/kb/`（过渡）/ 飞书多维表格（可选正式） | `kb://` | 统一检索入口 | 索引而非文件 |
| 大文件层（本期不启用） | NAS `Z:\` | `nas://<相对路径>` | 超大视频等，人类自行备份 | 原件 |

- 索引权威位置由人类裁决；未裁决前用过渡位置，不自建第三套索引。

## 2. 单一原件原则

- 每个文件有且仅有一个原件位置；其他位置只能是副本/缓存，索引中 `copy_of` 必填。
- 修改只改原件，再按需重新生成副本；禁止在副本上单独修改形成双活。
- 人类指定的知识库外文件夹：原件仍在原位置，网盘上传只登记批次记录，不把它迁入 `~/.agent-docs`。

## 3. 命名约束（强制委派 zhn-docs-std）

- 进入 `~/.agent-docs` 的**主文件/索引文件**一律 `YYMMDD｜类型｜主题.扩展名`；批量 ≥2 文件按 zhn-docs-std v1.3.0 §5（批次目录 + 主文件 + 唯一关联子目录，关联文件保持原名）。
- 命名、类型段归纳、≥4 字确认、撞名核对全部调用 `zhn-docs-std`；本技能不自行发明标签、不替用户确认。
- 上传网盘/飞书的副本**沿用原件文件名与相对路径**，不在云端另起命名体系。
- 引用知识库文件用第 1 节 URI，不写本机绝对路径。

## 4. 索引

- 文件级字段：`doc_id`、`文件名`、`yymmdd`、`类型段`、`主题`、`批次目录`、`相对路径`、`后端`、`后端路径或 file_id`、`size`、`sha256`、`mime`、`密级`、`copy_of`、`status`、`origin_device`、`origin_agent`、`created_at`、`updated_at`、`share_state`、`tags`。
- 版本戳字段（第 7 节使用）：`version_sha256`、`origin_updated_at`、`updated_by`、`backend_ref`（飞书 file_token + 后端修改时间；网盘 fs_id + server_mtime + 上传时 sha256）。
- `doc_id` 由 `sha256 + 后端 + 后端路径` 派生，幂等；`status ∈ active / pending / pending_orphan / missing`。
- 批次级字段见第 6 节；文件级明细只进 manifest，不灌进多维表格。
- 分享链接默认不写入索引；**提取码永不落索引、Git、共享记忆、handoff**。

### 4.1 写入流程（两阶段，可恢复）

1. 本地：命名 → 流式 sha256 → 索引查重 → 写 `status=pending`。
2. 上传 → 用 `file_meta`/`file_list` 回读核对大小与路径 → 置 `active`，同时写版本戳。
3. 失败：置 `pending_orphan` 并报告人类；不自动重传、不自动删除。
4. 重复写入：sha256 相同则去重复用；同名不同 sha256 走 zhn-docs-std 撞名流程，等待人类确认。

### 4.2 检索与取回

- 先查索引再按后端取回；网盘侧可用 `file_keyword_search` / `file_semantics_search` 辅助定位，但不替代索引。
- 取回前必须做第 7.2 节的读前校验。
- **官方 MCP 无下载/转存/读正文工具**：恢复默认由人类在网盘客户端手动完成；如需 Agent 自动恢复，须另行批准 WSL + 官方 Skill。
- 缓存到本会话临时目录，按 sha256 复用，用毕清理。

### 4.3 对账

- 只读比对索引/manifest 与后端列表，输出孤儿与缺失清单交人类；不自动修复、不自动删除。

## 5. 分流判断（按顺序取第一个命中项）

1. 密级 secret → 仅本机指定安全位置，禁止外云与分享，流程终止并提示。
2. 属于 `~/.agent-shared` 的文本/配置 → 仅 Git，不上云。
3. 超大视频、大型二进制 → 不纳入知识库，提示人类自行备份。
4. Agent 产出文档 / 人类指定文档 → `~/.agent-docs`（`docs://`），命名按第 3 节。
5. 需备份或对外交付 → 百度网盘副本（`pan://`），默认不生成分享链接。
6. 需在线预览/多人协作（可选层）→ 飞书副本；md 导入为飞书文档，html 不承诺在线预览；>20MB 走分片。
7. 人类指定文件夹批量上传 → 进入第 6 节，不按单文件大小分流。

## 6. 批量文件夹上传（单文件不大、数量大、总大小可超 100MB）

### 6.1 上传前必须输出并等待人类确认

- 源路径、文件数、总大小、预计请求数、目标根路径、模式（逐文件/打包分卷）、排除清单、是否生成分享链接。
- 排除：secret（账号/密钥/Token/证件）、隐藏与临时文件、符号链接不跟随；`~/.agent-docs/261111｜账号｜账号信息整理.html` 默认排除。
- 未获确认不得开始上传。

### 6.2 两种模式

- **逐文件模式（默认）**：保留目录结构逐文件上传。串行或并发 1；每 20 个文件暂停一次并汇报进度；失败记入失败清单，继续或中止由人类选择。
- **打包分卷模式**：文件数 >500、或无需网盘端逐文件预览/分享时推荐。本地打包（必要时分卷），网盘端只存包与 manifest，减少请求数与限流暴露。

### 6.3 manifest（两种模式都必须生成）

- 每条记录：`相对路径`、`size`、`sha256`、`状态`（pending/success/failed/skipped）、`网盘路径`、`错误信息`。
- 重入幂等：已 success 且本地 sha256 未变 → skipped；只在失败或内容变化时重传。
- manifest 存放：知识库内文件夹随批次目录保存；知识库外文件夹保存在本会话工作区，路径写入批次记录。

### 6.4 批次记录

- 字段：`batch_id`、源路径、模式、文件数、总大小、目标根路径、manifest 路径、状态、失败清单、起止时间、执行 agent/设备。
- 总大小 >100MB 只影响分批与打包策略，不触发改道 NAS。

## 7. 多设备同步与变更感知

### 7.0 只有三种得知途径

1. **写入方登记**（默认主渠道）：改文件的 agent/设备同批更新索引版本戳。
2. **读取方校验**：使用前对比本地版本与索引/后端元数据。
3. **事件推送**（可选增强）：仅飞书支持 `drive.file.edit_v1`；**百度网盘 MCP 无事件能力，只能轮询**。

**飞书文件被人直接在线编辑、未经过任何 agent 时，索引不会自动知道**；只能靠轮询飞书元数据或部署事件订阅发现，都不做则其他设备无从得知。这是当前零常驻服务架构的固有限制，必须向人类明示，不得承诺实时同步。

### 7.1 写后登记（必须）

- 上传/更新副本时同批更新索引版本戳与 manifest；未登记视为「未发布」，其他设备不负责发现。
- 登记内容：`version_sha256`、`origin_updated_at`、`updated_by`、`origin_device`、`backend_ref`。

### 7.2 读前校验（必须）

- 取文件前先读索引与后端元数据，对比本地缓存版本：一致则直接用缓存，不一致再拉取或提示。
- 元数据优先，sha256 只在元数据变化后重算；避免每次全量下载校验。

### 7.3 会话开始刷新（启用知识库时）

- 列出「自上次以来变化的条目」与各自状态，只报告，不自动下载、不自动覆盖。

### 7.4 状态判定与动作

| 状态 | 含义 | 动作 |
|---|---|---|
| clean | 本地/索引/后端一致 | 直接使用 |
| remote_newer | 后端或索引更新 | 提示并拉取；网盘无下载工具时提示人工 |
| local_newer | 本地改了未备份 | 提示需上传并登记 |
| conflict | 双方都改 | 停止，保留双方，交人类；不自动合并 Office/二进制 |
| copy_newer_than_origin | 飞书副本新于本机原件 | 告警，人类决定是否回流 |
| unknown | 仅 mtime/size 变化、无法校验内容 | 标疑似变化，不当作已同步 |

### 7.5 飞书副本被直接编辑

- 发现方式：轮询飞书元数据，或部署 `drive.file.edit_v1` 事件订阅（按 file_token、需文档管理权限与 `space:document.event:read` 等 scope、常驻接收进程，Webhook 或官方 SDK 长连接）。
- 发现后置 `copy_newer_than_origin` 并告警；**禁止自动用副本覆盖本机原件**。
- 确需回流时：导出 → 覆盖原件 → 重算 sha256 → 更新索引 → 重新生成其他副本，每步人类确认。

### 7.6 写冲突预防

- 乐观锁：上传前先读后端版本，若不等于自己基于的版本则停止并报告。
- 同一文件单 owner；批量任务锁 `batch_id` 与源路径；认领与锁记录写 `memory/org.md`。

### 7.7 轮询与事件订阅的启用门槛

- 默认只做「会话开始 + 读前」两次校验，不做后台轮询。
- 后台轮询或飞书事件订阅须人类批准后单独建自动化，限定目录与频率；事件订阅还需常驻进程与签名/重试/离线补拉设计。
- 若人类要求「飞书一改各设备即时自动同步」，属于把飞书升级为原件的架构迁移，须单独裁决并修订 rules.md 二-3，默认不启用。

## 8. 百度网盘 MCP 接入约束（官方 `baidu-netdisk/mcp`）

- **两种方式分工**：SSE（`https://mcp-pan.baidu.com/sse?access_token=…`）用于列表/元信息/搜索/复制/移动/重命名/建目录/分享/容量；**上传仅 stdio**（Python SDK + `uv run netdisk.py`，官方含 Windows 配置示例）。
- 工具清单**无下载、无转存、无读正文、无事件订阅**；不得声称具备这些能力。
- `file_upload_stdio` 的 `remote_path` 必须以 `/` 开头；不传则默认 `/来自：mcp_server`，本技能要求显式指定目标根路径。
- 授权目录范围**未声明 `/apps/bdpan` 沙箱**（那是官方 Skill 的限制），以实际开放平台应用与授权为准，首次使用前用 `file_list` 只读探测并记录，不假定能访问全盘。
- Access Token 属敏感凭证：SSE 模式下出现在 URL query，配置只写本机 `~/.workbuddy/mcp.json`，**禁止入 Git、禁止写入共享仓/日志/handoff/索引**；stdio 模式经 `BAIDU_NETDISK_ACCESS_TOKEN` 环境变量传入。
- 安装遵守 rules.md 四-1：先 `tools-scan.sh --check`；`uv` 放 `~/.agent-tools/bin/`；官方 Python SDK 源码放 `~/.source-repos/`；禁止全局/用户级安装。
- 官方 Skill（`BaiduNetdiskAIBot/bdpan-storage`）仅作下载/转存补充，需 WSL2 或 Linux；Windows 原生不得安装。
- 新增/修改 MCP Server 后需人类在连接器管理页点「信任」才生效。

## 9. 安全红线

- 密级：`public / internal / confidential / secret`；secret 禁止上云、禁止分享。
- 分享：默认关闭；仅人类当次明确指令才生成，优先短有效期；链接与提取码只在当次回复给人类。
- 凭证：飞书 `app_secret` 等放 `~/.agent-shared/config/`（0600，禁 Git）；网盘 Token 按第 8 节管理，禁读、禁输出、禁转发。
- 云同步目录内的删除、移动、冲突处理由人类在客户端 UI 完成；网盘侧 `file_del`/`file_move`/`file_rename` 需人类明确确认。

## 10. 多 Agent 协同

- 任务认领：`memory/org.md` 追加 `[doing]`（任务ID / owner / worktree / 锁定文件），完成后 `[done]`；涉他任务留 handoff。
- 同一文件同一时间只允许一个 owner 写；索引与 manifest 写入幂等，不覆盖他人记录。
- 同一批量任务同一时间只允许一个 agent 执行，认领时锁定 `batch_id` 与源路径。
- 不改他人未提交改动；共享仓提交只 `git add` 自己产出的路径，禁止 `git add -A`。

## 11. 限流与退避

- 网络/限流失败：指数退避（1s→2s→4s→8s→16s，至多 5 次），记录错误码与触发阈值。
- 批量串行并加间隔，不并发打满配额；连续失败即停并报告，不更换未授权通道绕过。
- 记录上传速度、失败率、跳过数，写入当次任务报告（实测数据不入长期记忆）。
