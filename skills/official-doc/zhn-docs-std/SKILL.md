# zhn-docs-std — agent-docs 文件命名规范

## 1. 目的与适用范围

- 仅为保存到 `~/.agent-docs`（文档实时同步区）的文件提供命名规范与文件名建议。
- 仅在用户明确指定「保存到 agent-docs」或明确指示修改 `~/.agent-docs` 中文件的内容/文件名时触发。
- 对保存到该目录的文件一律适用，不按扩展名区分（`.md`/`.txt`/Office/PDF/图片等同等处理）。
- 不约束当前工作区文件夹或任何其他目录中的文件；不处理云端资料库节点、在线文档标题。
- 作为纯规范技能运行：只输出命名建议与校验结论，不创建、重命名、移动、删除、覆盖或上传任何文件，不调用其他技能、脚本或外部服务。

## 2. 命名格式

`MMDD｜类型｜主题.扩展名`

- 分隔符为全角竖线 `｜`（U+FF5C）；一个文件名中恰好出现两个，类型段居中。
- MMDD 取 Asia/Shanghai 日期，月、日各两位补零。新建文件取保存到 agent-docs 的当日；修改已有文件时保持原 MMDD，除非用户明确要求按修改日更新。
- 主题段概括文件内容，保留用户原有用词；不得包含 `｜`，以免破坏三段结构。
- 扩展名保持源文件类型不变，不计入三个命名段。

## 3. 类型段生成规则

- 读取（或依据用户给出的）文件内容后，由 agent 自行总结类型；**不设候选列表、不提供枚举、不从预设标签中挑选**。
- 取 2–3 个汉字，或恰好一个英文单词（如 `Skill`、`Docker`）；单个英文单词视为合法类型，不计为中英混排。
- 归纳结果达到 4 个字及以上（含 4）时，触发第 4 节的用户确认流程，不得直接采用。
- 禁止出现：1 个字；以数字开头；中英混排（如 `Agent调试`）；含 `｜`、空格、`/`、`、`（顿号）；以纯数字或纯符号构成。
- 同一主题在 agent-docs 中已有既用类型标签时，优先复用；拟采用新标签或与既用标签不一致时，提示用户确认是否修改，不擅自新造近义标签。
- 内容宽泛、无法归纳出可辨识类型时，兜底用 `其他`。

## 4. 类型确认流程

1. 输出归纳出的类型词及依据（基于文档内容的哪些特征）。
2. 类型达到 4 个字及以上（含 4）时，列出两个选项：① 压缩到 2–3 字并给出建议词；② 保留原词照用。同时说明可改用一个英文单词。
3. 等待用户明确回复后再确定类型；确认前不输出最终文件名、不写入任何文件。
4. 用户确认保留原词时允许原词照用（不受 2–3 字限制）；用户改用英文单词时按第 3 节英文规则校验。

## 5. 输出约定

- 给出完整文件名建议（`MMDD｜类型｜主题.扩展名`）、类型归纳依据、MMDD 取值日期。
- 同时给出校验结论：分隔符数量、类型段长度与字符合法性、主题段是否含 `｜`。
- 修改已有文件的内容时不主动改动文件名；仅当用户明确要求改文件名、或指出原名需规范化时，给出建议名并说明与原名的差异。
- 不主动扫描 `~/.agent-docs` 目录、不列出目录内容、不批量生成改名清单。

## 6. 边界（禁止事项）

- 不执行任何写操作：不创建、不重命名、不移动、不删除、不覆盖、不上传。
- `~/.agent-docs` 属第三方同步目录；同步冲突与删除一律由人类在同步客户端处理，不在本地侧做删除或重试。
- 不加载 builtin `library` 或任何其他技能，不依赖鉴权、脚本、环境变量或网络。
- 不约束非 agent-docs 路径中的文件，不处理云端资料库节点命名。

## 7. 共享与同步（供其他 agent / 其他设备）

- 权威原件：`~/.agent-shared/skills/official-doc/zhn-docs-std/SKILL.md`，随共享仓 Git 同步到 origin/backup 双远端。
- 平台安装副本：`~/.workbuddy/skills/zhn-docs-std/SKILL.md`，为 WorkBuddy 会话的加载入口；本副本于 2026-11-11 由权威原件单向复制生成。
- 两处内容同源；修改只改权威原件，再单向复制到安装副本，禁止在副本上单独修改造成双活版本。
- 其他设备或 agent：先 `git pull` 共享仓，再把源码目录复制到本机 `~/.workbuddy/skills/zhn-docs-std/`；或解压分发的 `zhn-docs-std.skill` 包。用 SHA256 比对两处 SKILL.md 确认一致。
- 记忆与交接文档中引用 agent-docs 文件时使用 `docs://<相对 ~/.agent-docs 的路径>` 约定。

## 8. 示例

- 11 月 2 日保存「stockdb 量化分析使用说明」到 agent-docs：归纳内容为研究方法说明 → `1102｜研究｜stockdb 使用方法与量化分析指南.md`。类型由内容归纳，非从列表选取。
- 类型超长触发确认：归纳出「量化数据接口」（6 字）→ 输出「压缩为『量化』」与「保留原词」两选项并等待确认；用户回复「用 API」→ 最终 `1102｜API｜股票数据接口汇总.md`。
- 兜底：内容杂乱无法归纳 → `1102｜其他｜临时资料汇总.md`。
- 同主题复用：同主题既有标签为「研究」，新归纳出「调研」→ 提示用户确认是否统一为「研究」，不擅自采用新词。
