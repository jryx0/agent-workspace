# zhn-docs-std — agent-docs 文件命名与批量目录结构规范

## 1. 目的与适用范围

- 仅为保存到 `~/.agent-docs`（文档实时同步区）的文件提供命名规范、文件名建议，以及批量生成多文件时的目录结构方案。
- 仅在用户明确指定「保存到 agent-docs」或明确指示修改 `~/.agent-docs` 中文件的内容/文件名时触发。
- **按角色区分适用范围**（v1.3.0）：
  - **主文件／索引文件**：一律适用第 2 节命名格式，不按扩展名区分（`.md`/`.txt`/Office/PDF/图片等同等处理）。
  - **关联文件**（放入第 5 节关联子目录的代码、脚本、页面、素材等）：**豁免**第 2 节命名格式，保持常规原名，不规范化。
- 不约束当前工作区文件夹或任何其他目录中的文件；不处理云端资料库节点、在线文档标题。
- 作为纯规范技能运行：只输出命名建议、目录结构方案与校验结论，不创建、重命名、移动、删除、覆盖或上传任何文件与目录，不调用其他技能、脚本或外部服务。
- **人类单文件豁免**：人类可对单个文件明确指示「按原文件名保存、不按本规范执行」；该豁免仅对该文件、当次有效，agent 照办并在回复中注明「按人类指示保留原名，未规范化」。未获明确指示时一律按本规范出建议名；agent 不主动建议豁免，也不把一次豁免推定为通用偏好。此条款与第 5 节的关联文件豁免是两套独立机制，不可互相扩大解释。

## 2. 命名格式

`YYMMDD｜类型｜主题.扩展名`

- 分隔符为全角竖线 `｜`（U+FF5C）；一个文件名中恰好出现两个，类型段居中。不使用半角 `|`，文件名前不留空格。
- YYMMDD 取 Asia/Shanghai 日期，**两位年份居前**，月、日各两位补零（如 2026 年 11 月 2 日 → `261102`）。新建文件取保存到 agent-docs 的当日；修改已有文件时保持原 YYMMDD，除非用户明确要求按修改日更新。
- 主题段概括文件内容，保留用户原有用词；不得包含 `｜`，以免破坏三段结构。
- 扩展名保持源文件类型不变，不计入三个命名段。

## 3. 类型段生成规则

- 读取（或依据用户给出的）文件内容后，由 agent 自行总结类型；**不设候选列表、不提供枚举、不从预设标签中挑选**。
- 取 2–3 个汉字，或恰好一个英文单词（如 `Skill`、`Docker`）；单个英文单词视为合法类型，不计为中英混排。
- 归纳结果达到 4 个字及以上（含 4）时，触发第 4 节的用户确认流程，不得直接采用。
- 禁止出现：1 个字；以数字开头；中英混排（如 `Agent调试`）；含 `｜`、空格、`/`、`、`（顿号）；以纯数字或纯符号构成。
- 同一主题在 agent-docs 中已有既用类型标签时，优先复用；拟采用新标签或与既用标签不一致时，提示用户确认是否修改，不擅自新造近义标签。
- 内容宽泛、无法归纳出可辨识类型时，兜底用 `其他`。
- 本节的长度与字符约束同样适用于第 5 节的**批次目录名**与**关联子目录名**（二者不带日期前缀、不带扩展名）。类型段与目录名是**两个独立概念**：前者概括单份文件内容，后者概括整批任务。

## 4. 类型确认流程

1. 输出归纳出的类型词及依据（基于文档内容的哪些特征）。
2. 类型达到 4 个字及以上（含 4）时，列出两个选项：① 压缩到 2–3 字并给出建议词；② 保留原词照用。同时说明可改用一个英文单词。
3. 等待用户明确回复后再确定类型；确认前不输出最终文件名、不写入任何文件。
4. 用户确认保留原词时允许原词照用（不受 2–3 字限制）；用户改用英文单词时按第 3 节英文规则校验。
5. 批次目录名、关联子目录名的归纳结果达到 4 个字及以上时，同样按本流程确认；不得为追求「尽量简短」而跳过确认或擅自截断。

## 5. 批量多文件的目录结构（v1.3.0 新增）

### 5.1 触发条件

- 一次任务产出到 `~/.agent-docs` 的文件数 **≥ 2**（主文件／索引文件与关联文件合计），启用本节。
- 恰好 1 个文件 → **不建批次目录**，直接放用户明确指定的目标路径，按第 2 节命名。
- 用户指定的目标路径是既定前提，技能不自行推断、不改写、不往上加层；目标路径不存在时由执行 agent 负责创建，技能只输出路径方案。

### 5.2 结构

```
<用户指定的目标路径>/
└── <批次目录>/                        ← 新建，一层
    ├── YYMMDD｜类型｜主题.ext         ← 主文件／索引文件，1 个或多个
    ├── YYMMDD｜类型｜主题.ext
    └── <关联子目录>/                  ← 仅当存在关联文件时建，一层、不嵌套
        ├── <关联文件原名>
        └── <关联文件原名>
```

- 批次目录与关联子目录都只建一层；关联子目录不再嵌套下级目录。
- 没有关联文件时**不建空子目录**。

### 5.3 批次目录名

- 概括本批次的**共同主题／任务短名**（如 `重建`），与文件名中的「类型段」是两个独立概念；主文件各自按第 3 节归纳自己的类型，不要求与目录名一致，也不要求彼此一致。
- 不带日期前缀、不带扩展名，尽量简短。
- 长度与字符约束复用第 3 节：2–3 个汉字或恰好一个英文单词；≥4 字走第 4 节确认流程；禁 1 字、数字开头、中英混排、`｜`、空格、`/`、`、`、纯数字/纯符号。
- 由 agent 自行归纳，**不给候选列表**；不做「同主题标签复用」提示（批次名是一次性的任务短名，不属于标签体系）。

### 5.4 主文件／索引文件

- 放在批次目录**顶层**，数量 1 个或多个；每份独立按 `YYMMDD｜类型｜主题.扩展名`（第 2–4 节）命名，各自归纳类型段、各自概括主题段。
- 同批文件的 YYMMDD 取同一个「保存到 agent-docs 的当日」。
- 主题段须能互相区分，避免同批出现重名文件。
- **索引文件**：承担总览／入口作用的文件，**按任务需要可能生成，非必选、不强制**。生成时与其他主文件**完全同规则**命名，不额外要求 `index.md`／`README`，不单独设命名规则。

### 5.5 关联子目录与关联文件

- 只建**一个**关联子目录，所有关联文件（不论类型）同放其中。
- 目录名由 agent **只推荐一个**、不给候选列表，尽量简短；长度与字符约束复用第 3 节（2–3 汉字或单个英文词，如 `脚本`、`assets`），≥4 字走第 4 节确认流程。
- 关联文件**保持常规原名**（如 `data.py`、`sync.html`），不套第 2 节格式、不重命名、不加日期前缀。

### 5.6 撞名检查（只读）

- 输出方案时，应提示调用方 agent 对**用户指定目标路径的下一层子目录名**做**一次只读查看**（仅该层、不递归、不列全库、不写）。
- 若已存在同名批次目录 → 给出「复用该目录／换一个新名」两个选项并**等待用户确认**，不自动复用、不自动覆盖、不擅自改名。
- 本技能自身不执行该查看（纯规范、零工具调用）；调用方未提供目录信息时，按用户给出的信息出方案，并在输出中附上「建议先核对同名目录」的提示。

### 5.7 职责边界与既有目录

- 本节只定义**结构方案的输出内容**；实际创建目录与文件由调用本技能的执行 agent 完成，本技能不创建任何东西（第 7 节禁写不变）。
- `~/.agent-docs` 中既有的「目录名≈文件名」旧目录（如 `技术资料/0924｜文档｜多agent协同提示词/`）**只兼容、不迁移、不改名**；存量 `docs://` 引用不因本节调整。

## 6. 输出约定

- 给出完整文件名建议（`YYMMDD｜类型｜主题.扩展名`）、类型归纳依据、YYMMDD 取值日期。
- 同时给出校验结论：分隔符数量、类型段长度与字符合法性、主题段是否含 `｜`。
- 批量场景（第 5 节）额外输出：① 目录结构树；② 批次目录名及归纳依据；③ 每个主文件／索引文件的建议名与类型依据；④ 关联子目录的唯一推荐名；⑤ 关联文件清单（原名，标注「豁免规范化」）；⑥ 第 5.6 节撞名核对提示；⑦ 校验结论。
- 修改已有文件的内容时不主动改动文件名；仅当用户明确要求改文件名、或指出原名需规范化时，给出建议名并说明与原名的差异。
- 除第 5.6 节允许并交由调用方执行的一次只读查看外，不主动扫描 `~/.agent-docs` 目录、不列出全库内容、不批量生成改名清单。

## 7. 边界（禁止事项）

- 不执行任何写操作：不创建（含目录）、不重命名、不移动、不删除、不覆盖、不上传。
- 不执行工具调用：不扫描目录、不读密钥、不联网；第 5.6 节的只读查看由调用方 agent 执行，本技能只输出提示。
- `~/.agent-docs` 属第三方同步目录；同步冲突与删除一律由人类在同步客户端处理，不在本地侧做删除或重试。
- 不加载 builtin `library` 或任何其他技能，不依赖鉴权、脚本、环境变量或网络。
- 不约束非 agent-docs 路径中的文件，不处理云端资料库节点命名。

## 9. 示例

- 11 月 2 日保存「stockdb 量化分析使用说明」到 agent-docs：归纳内容为研究方法说明 → `261102｜研究｜stockdb 使用方法与量化分析指南.md`。类型由内容归纳，非从列表选取。
- 类型超长触发确认：归纳出「量化数据接口」（6 字）→ 输出「压缩为『量化』」与「保留原词」两选项并等待确认；用户回复「用 API」→ 最终 `261102｜API｜股票数据接口汇总.md`。
- 兜底：内容杂乱无法归纳 → `261102｜其他｜临时资料汇总.md`。
- 同主题复用：同主题既有标签为「研究」，新归纳出「调研」→ 提示用户确认是否统一为「研究」，不擅自采用新词。
- 人类豁免：用户明确说「这个就用原名 `tool-config.yaml` 保存」→ 直接采用原名并注明「按人类指示保留原名，未规范化」，不输出规范化建议名。
- **批量（用户指定保存到 `agent-docs/股票/引擎/`，一次产出 2 份主文档 + 2 个关联文件）**：本批任务归纳为「重建」，两份主文档各自归纳类型 →

  ```
  股票/引擎/重建/
  ├── 261111｜数据｜xxxx.md
  ├── 261111｜环境｜xxxx.md
  └── 脚本/
      ├── data.py
      └── sync.html
  ```

  `脚本` 是关联子目录的唯一推荐短名；`data.py`／`sync.html` 按 §5.5 保持原名、不规范化。示例中的 `261111` 为示意，实际取保存到 agent-docs 的当日。
- **索引文件按需**：同一批次若任务需要一份总览，可再加 `261111｜总览｜引擎重建总览.md` 放在顶层，与其他主文件同规则命名；不需要时不必生成，也不额外建 `index.md`／`README`。
- **触发边界**：一次只产出 1 份文档 → 不建批次目录，直接 `股票/引擎/261111｜数据｜xxxx.md`；2 份主文件但 0 个关联文件 → 建批次目录、不建空子目录。
- **撞名**：目标路径下已存在 `重建/` → 输出「复用该目录／换一个新名」两选项并等待用户确认，不自动复用、不覆盖。
